Existing XML conversion to four independent rates
Date: 2026-11-06
Branch: convert-four-rate-xml_AI

Script: simulate/XMLgenerator/convert_to_four_rates.py
Dependencies: Python 3.6+ standard library only (compatibility fix: 2026-11-07).

Usage from PHYFUM:
  python3 simulate/XMLgenerator/convert_to_four_rates.py analysis.xml
    Creates analysis_4param.xml.
  python3 simulate/XMLgenerator/convert_to_four_rates.py analysis.xml --suffix _four
    Creates analysis_four.xml.
  python3 simulate/XMLgenerator/convert_to_four_rates.py analysis.xml chosen.xml --suffix _four
    Creates exactly chosen.xml; analysis filenames still receive _four.

The suffix is inserted before the final extension of every fileName and
operatorAnalysis attribute. Directories are preserved. This includes .ops,
.log and .trees outputs, MLE logs, and corresponding analysis readers.
For example results/run.MLE.log becomes results/run.MLE_4param.log.

Nu copies mu's initial value and bounds into an independent parameter; zeta
copies gamma's. The converter clones each source rate's actual scale operator
and prior, including customized tuning and prior settings. It adds references
to the new rates to joint upDownOperator groups and existing rate log entries
(including columns). Cloned operators/priors with IDs receive distinct IDs.
Source rate definitions referenced through idref are resolved before copying.
Conventional flipflop.mu/flipflop.gamma IDs produce flipflop.nu/flipflop.zeta;
custom IDs are supported too. XML comments and sequence content are preserved,
though XML serialization can normalize attribute quoting and empty-tag spacing.

The converter expects one defined flipflopModel and the generator's scalar
parameter, scaleOperator and prior structure. It rejects already expanded XML,
missing priors/operators, ID collisions, and nonpositive/nonfinite initial
values (which cannot initialize the new scale proposals correctly). Errors
are reported before writing output. Existing output XMLs and the source XML
are protected from overwrite. Empty suffixes and path separators in suffixes
are rejected.

Compatibility fix, 2026-11-07 (four-rate-params_AI)
-------------------------------------------------
The insert_comments keyword was introduced in Python 3.8; older interpreters
raised TypeError when constructing the XML parser. Replaced that keyword with
a TreeBuilder subclass using start/data/end callbacks to preserve comments
inside the root, including commented alternative configurations. Comments
outside the root are ignored, matching ElementTree's previous behavior.
The converter now uses standard-library interfaces available in Python 3.6.
Also replaced Python 3.7-only subprocess test arguments with older equivalents.

All six converter tests passed, including a new comment/text preservation
regression and the existing full CLI conversion tests. git diff --check passed.
These checks ran on the installed Python; Python 3.6/3.7 were not available
for direct runtime verification. No dependencies added.
