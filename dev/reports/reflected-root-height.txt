XML configuration (inside <operators>, example with fixed LCA height 45)
----------------------------------------------------------------------
  <randomWalkOperator windowSize="2.5" weight="3.0"
                      boundaryCondition="reflecting" upper="45.0"
                      autoOptimize="true">
      <parameter idref="treeModel.rootHeight"/>
  </randomWalkOperator>

The generator uses the same age for this upper limit and luca_height. There
is deliberately no explicit lower attribute: TreeModel's root parameter
supplies the current maximum of its two child heights. TreeModel preserves
the root parameter's identity when a topology edit replaces the root node,
so both the target and its lower bound continue to refer to the current root.

Only the root height changes. With H the fixed LCA height, R the root height,
and L the oldest-child height, the proposal reflects R+U[-w,w] into [L,H].
Multiple boundary crossings are reflected, not clipped or resampled. The
interval is unchanged by this root-only move, so its log Hastings correction
is zero. The existing heightRules=true likelihood derives luca_branch=H-R.
Neither luca_branch nor luca_height receives an independent operator.

The initial window is 2.5 time units (years in generated XML), the weight is
3, and automatic tuning is enabled. These are initial settings, not an
empirically optimized recommendation. The original root scaler, tree/topology
operators, rate/tree up-down move, and every prior are retained unchanged.

Scope and assumptions
---------------------
This configuration is for a fixed LCA with a valid initial tree and a
nondegenerate interval L<H. It is not a solution for a moving LCA: a literal
upper limit would not follow a sampled cenancestor height. If the fixed age
is edited manually, update both luca_height and the operator's upper limit.
The XML generator keeps them synchronized automatically.

Adding the move to an existing XML
----------------------------------
simulate/XMLgenerator/add_mrca_sampling.py adds the reflected move to an
existing fixed-LCA PHYFUM XML. It uses only the Python standard library and
APIs available in Python 3.6.8.

Run from PHYFUM:
  python3 simulate/XMLgenerator/add_mrca_sampling.py analysis.xml
  python3 simulate/XMLgenerator/add_mrca_sampling.py analysis.xml --suffix _trial
  python3 simulate/XMLgenerator/add_mrca_sampling.py analysis.xml chosen.xml --suffix _trial

The first command creates analysis_MRCASampling.xml next to the input. The
suffix also goes before the final extension in fileName and operatorAnalysis
attributes (e.g. run.log becomes run_MRCASampling.log and run.MLE.log becomes
run.MLE_MRCASampling.log). Log writers and their MLE/HME analysis readers
receive matching filenames. Directory components and the interpretation of
relative paths are preserved. An explicit second positional path is used
exactly as given, with the suffix still applied to names inside the XML.

The script finds the likelihood's root parameter and reads its fixed
cenancestorHeight, including through an idref. It uses the settings shown
above and preserves the existing operators, rates, priors, data, and XML
comments inside the document. XML formatting and quote style can change
during serialization.

The input must define one cenancestorTreeLikelihood with heightRules=true,
one operator schedule, a positive finite scalar LCA height, and an identified
root-height parameter. The script rejects a sampled LCA, an existing root
randomWalkOperator, and an empty suffix or one containing path separators.
It creates the output exclusively to protect the input and existing files.

Other tree proposals
--------------------
The move does not add a global root bound to other operators; their existing
stem prior still rejects roots older than the fixed LCA.

Simulation study
----------------
In the user's simulation study, adding the reflected move did not change
the observed accuracy of luca_branch estimates or overall accuracy. The
effective sample size (ESS) of luca_branch improved with the new operator.
The study found no statistically significant association between the ESS
improvement and luca_branch length. The results therefore leave open whether
the gain came from the reflected proposal itself or from proposing more
updates to the MRCA height, which determines luca_branch. A comparison with
matched total weight for root-height proposals would help distinguish these
explanations.
